# 局域网设备发现 v2.3.6

发布日期：2026-11-17

## 本版重点：发现引擎逻辑优化

本版不改变应用的只读与隐私边界（仍不扫描端口、不上传 MAC / IP / 扫描结果），集中优化扫描引擎的健壮性、发现率、扫描时长与 UI 刷新效率。

## 健壮性修复

| 问题 | 修复 |
|---|---|
| 个别 OEM 的 NSD 实现可能丢失 `onDiscoveryStarted` / `onDiscoveryStopped` 回调，导致扫描协程永久挂起、界面停留在“正在扫描” | 为每个 mDNS 服务类型发现增加看门狗硬超时（窗口 + 2.5 秒）；即使回调全部丢失，协程也保证按时结束 |
| 停止定时消息在完成后仍可能残留触发 | 结束时统一移除 `postDelayed` 回调，`requestStop` 幂等 |
| mDNS `resolveService` 并发调用在 API 34 之前会被系统拒绝，导致部分设备证据丢失 | 新增串行化解析队列（互斥锁逐个执行），单次解析 2.5 秒超时、整队列 7 秒总预算，超预算跳过并记录诊断 |
| 扫描完成统计可能早于 mDNS 解析结果到达，完成消息中的设备数偏小 | 扫描收尾阶段等待解析队列清空（受预算约束）后再生成汇总，统计与列表一致 |

## 发现率提升

- 组播阶段（mDNS / SSDP）结束后**二次读取 `/proc/net/arp`**：组播流量会补全内核邻居缓存，可捕获扫描开始前不可见的设备，并把 MAC 证据自动合并到已由协议证据发现的设备上；已有相同 MAC 的条目会被跳过，不重复计数。
- SSDP `M-SEARCH` 在窗口中段（1.5 秒）**补发一次重传**，缓解 Wi-Fi 组播丢包导致的漏发现。
- SSDP 同一物理设备按不同 ST / USN 返回的多条响应，现按 USN 中的 UDN 聚合为单一设备，并在“UPnP 设备类型”中累计显示全部类型；重复报文直接丢弃。
- 型号识别：IPP 端口选择不再把 SSDP 固定端口 1900 当作打印机 IPP 端口。

## 扫描提速

| 参数 | v2.3.5 | v2.3.6 |
|---|---|---|
| mDNS 服务类型并行度 | 3（10 种类型分 4 轮，约 7-8 秒） | 5（约 2 轮，约 3-4 秒） |
| mDNS 单类型监听窗口 | 1800 ms | 1500 ms |
| SSDP 监听窗口 | 4500 ms | 5000 ms（覆盖重传后的完整响应期） |
| SSDP 接收缓冲 | 每报文新建 4 KB | 循环内复用（接收前重置长度） |

## UI 刷新效率

- 设备注册表采用**脏标记合并发布**：SSDP 突发响应等同一帧内的多条证据只触发一次主线程快照推送，扫描结束前再强制发布一次最终快照；显著降低扫描高峰期的重组压力。
- 系统网络回调（`onCapabilitiesChanged` 等密集触发）增加 **400 ms 去抖**，连续回调合并为一次网络状态刷新，减少 Binder 调用风暴。
- OUI 同步进度提示改用 `isOuiSyncing` 状态判断，修复任务启动初期进度消息被丢弃的问题。
- 热点扫描完成消息改用注册表直接统计的“公开服务设备数”，不再以差值估算。

## 其他

- 各协议请求的 `User-Agent` 统一为 `LanDeviceDiscovery/2.3.6`。
- mDNS TXT 身份规范化改为单次遍历，去掉重复的链式映射。
- 诊断日志新增 `arp.refresh`（二次邻居读取）与 mDNS 解析队列的预算 / 超时事件，便于排查。
