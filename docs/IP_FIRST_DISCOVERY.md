# 先发现 IP，后手动扫描端口

## 扫描阶段分离

从 2.0.1 起，应用将网络发现和端口检查分为两个明确阶段。主页“扫描设备”只收集能直接证明设备 IP 存在的协议证据，不会对子网地址发起 TCP 或 UDP 端口连接。设备详情中的“端口扫描”按钮才会对用户已选择的一台设备执行受限的固定服务端口连通性检查。

| 阶段 | 触发方式 | 允许的网络行为 | 结果 |
|---|---|---|---|
| IP 发现 | 用户在主页开始扫描 | 读取 ARP/邻居缓存、mDNS/DNS-SD 发现、SSDP M-SEARCH 与 UPnP 公共描述请求 | 已发现设备的 IP、MAC（若可获得）、主机名、公开型号、服务来源 |
| 单设备端口扫描 | 用户进入已发现设备详情并点击按钮 | 仅对该设备 IP 的固定常见服务端口建立 TCP 连接 | 开放端口与服务标签 |
| 在线监测 | 用户在设备详情中明确开启 | 仅对用户选择设备的已知或常见服务端口进行前台连通性检查 | 在线或未确认状态 |

## 发现范围

普通 Android 应用不能使用原始 ARP 请求或 ICMP Echo 来枚举整个 Wi‑Fi 子网。因此，默认发现不保证列出未产生邻居记录、且不广播 mDNS 或 SSDP 服务的所有设备。应用会清楚显示每台设备的发现来源，而不会把未验证的 IP 地址、端口连接结果或随机探测响应伪装成设备。

若设备只在系统热点客户端表中可见、但不广播网络服务且系统禁止读取邻居缓存，普通第三方应用无法在无系统权限的前提下可靠显示该设备。此限制不应通过后台端口扫描绕过。

## 验证

在普通 Wi‑Fi 下开始一次主页扫描后，`LanDiscovery` 日志不应出现 `IP 服务探测`，扫描汇总中的检查端口数应为零。选择一台设备并开始详情页端口扫描后，才会出现该设备的 TCP 连通性结果。详情页端口扫描通过当前 Wi‑Fi `Network` 绑定套接字，避免在存在 VPN 时误走默认网络。
